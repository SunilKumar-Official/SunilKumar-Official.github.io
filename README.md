# Sunil Kumar: personal website

A static, multi-page site (HTML, CSS and JavaScript) hosted on GitHub Pages. `index.html` and the
`about/`, `experience/`, `projects/` (including its case-study pages), `contact/`, `testimonials/` and
`posts/` directories are all generated by `python3 tools/generate_pages.py`, which combines the shared
page chrome (nav, footer, `<head>`) with per-route content fragments. The Experience, Testimonials, Posts
and Projects pages also render data-driven content from `data/data.js`, which is generated separately from
the JSON files in `data/` (including `career.json`). Re-run `tools/generate_pages.py` after editing a
content fragment or the shared chrome; re-run the `data/` pipeline (below) after editing the JSON content.

## Preview locally

Run `python3 -m http.server` in the repo root and open `http://localhost:8000/` — the generated pages use
root-relative paths (e.g. `/assets/site.css`), so serving over HTTP rather than opening `index.html` as a
`file://` URL keeps those paths resolving correctly.

## Keep the content up to date

All commands run from this folder with `python3`. Nothing is published until you review it.

1. Download your LinkedIn data. The menu names may differ; look in Settings and Data privacy for
   "Get a copy of your data". The download usually arrives within a day or two. Keep it in Downloads or in
   `private/linkedin-export/`, never in the repo folder root.
2. `python3 tools/import_linkedin.py <the downloaded folder or .zip>` adds new posts and recommendations as drafts.
3. `python3 tools/review.py` steps through the drafts: publish, edit, skip or discard. A testimonial cannot be
   published until its consent is set. Discarded items are remembered and are not brought back by the next import.
4. `python3 tools/check.py` checks the public data. Fix any errors it reports.
5. Push the change. First run `gh auth status` and check it shows `SunilKumar-Official`. Then:
   `git add data`, `git commit -m "Update posts"`, `git push`. GitHub Pages updates in about a minute.

Add one item without an export:

- `python3 tools/add.py post` or `python3 tools/add.py testimonial`. This is the way to add posts from other
  communities. Without `--draft` it publishes right after you answer `y`; add `--draft` to save it privately first.
- LinkedIn posts should come in through the import. A LinkedIn post added by hand from its browser link would
  later be imported again as a duplicate.

After editing a JSON file by hand, run `python3 tools/build_data.py`.

Drafts, raw exports and backups live in `private/`, which is never committed.

## Resume and QR codes

The Contact page offers a one-page resume PDF and a QR code that opens it. Both are generated, not hand-made:

1. Keep your contact details in `private/contact-details.json` (gitignored): `email`, `phone`, `city`, `region`, `country`.
   They are filled into the PDF only. They never appear in the site's HTML or data files, and a test guards that.
2. Edit the resume's layout and wording in `tools/resume/resume.template.html`.
3. Build: `.venv/bin/python tools/build_resume.py`. It writes `assets/Sunil-Kumar-Resume.pdf` and `assets/qr-resume.svg`,
   and fails without touching `assets/` if the resume would not fit on one A4 page. It needs Google Chrome
   (set `CHROME` if it is not at the usual macOS path).
4. One-time setup for the QR library: `python3 -m venv .venv && .venv/bin/pip install segno`. `.venv/` is gitignored.

The PDF contains your email and phone, so once pushed it is public and stays in git history.

## Logo, icons and link-preview image

`assets/favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` and `og-image.png` are rendered from `tools/brand/icon.html`
and `tools/brand/og.html` (open them through the preview server, then screenshot with headless Chrome: the og image at
1200x630, the icons via `icon.html?s=<size>`, adding `&sq=1` for the square touch icon). After changing any of them, bump the
`?v=` number in `_templates/page_shell.html`, because browsers and social sites cache these.

## Fonts

Jost, Playfair Display and Oswald are self-hosted in `assets/fonts/` (Latin subset, SIL Open Font License), so the site
makes no requests to Google at load time.
