KPI Scoring Pipeline

Business problem

Every team calculated performance differently. Some used a weightage-based model, others a slab-based one; Technical scored people on a point system instead of a percentage; Menu and Website applied "rider" deductions to incentive payouts that other teams didn't have; and Customer Service ran two separate, inconsistent methods — one for its monthly performance review, a different one for incentive payout — inside the same team. One team tracked most of its KPIs by hand in spreadsheets. On top of that, the underlying employee department/role mapping that every team's KPIs depended on had its own gaps and inconsistencies. None of it was comparable across departments, and most of it was calculated manually every month.

My contribution

I designed the standardized methodology end to end and built the pipeline that automates it — this wasn't a request to automate someone else's spreadsheet; the scoring model itself (what follows in Approach) is my design, documented and agreed with department stakeholders before being implemented.

Data & tools

Python and SQL against Amazon Redshift. A local CSV layer holds the KPI definitions (target, weight, direction) per role, since write access to the definitive KPI table wasn't available.

Scope & scale

100+ KPI metrics defined across every operational team (Customer Service, Apps, Kiosk, Menu, Website, Technical, Early Life, and others), each role assigned five core KPIs plus three gateway metrics. 500+ automated tests cover the scoring logic and output validation.

Approach

I designed one Combined Performance Score (CPS) methodology that works the same way for every role in every department, replacing the patchwork above:

  • Each role gets five core KPIs, weighted by that department's own stakeholders so the weightings still reflect what actually matters to each team — but the weights must sum to 100%, so they're always comparable.
  • Every KPI is converted onto the same scale: achievement percentage (target vs. actual), then multiplied by its weight, then summed into one CPS per person.
  • Three gateway metrics per role determine incentive eligibility without touching the CPS calculation itself — so performance measurement and incentive-qualification stay cleanly separate.
  • Employees are then stack-ranked: grouped by department, split into gateway-qualified vs. not, and ranked by CPS within each group. I documented a deliberate refinement here too — this ranking approach suits monthly incentive payouts well, but for annual performance reviews, I recommended weighting CPS more heavily than the gateway outcome, so one review cadence doesn't unfairly dominate the other.

On the engineering side: the pipeline matches employees to their KPI definitions, runs one validated SQL query per metric, computes CPS and rank, and writes a full run manifest and log so every run is traceable. A dedicated validation layer checks the output itself for problems — nulls, duplicates, wrong types, out-of-range values, unregistered metrics, missing audience coverage — and it has caught real data issues before they reached a report, including a case where a production query claimed to filter a field it actually didn't.

Outcome

This replaced a fragmented, inconsistent, largely manual process with one standardized, automated scoring methodology used across every team. It freed close to a full headcount per team that had been spent on manual data-gathering and calculation. The output now feeds HR's monthly and annual appraisal process and Finance's monthly incentive calculations directly — so the accuracy and consistency of this pipeline has a real, direct effect on how people are evaluated and paid.

Evidence

Not yet public — no sanitized repository exists for this project yet (a planned follow-up, not available for this round). Private evidence: a 500+-test automated suite, a documented run-validation layer, and the KPI standardization design itself.

Limitations & what's next

A small number of KPI definitions are still pending a working query — not every metric in the new framework has been fully ported yet. The incentive payout structure for at least one team is still under review as part of the broader rollout, separate from the scoring pipeline itself.
